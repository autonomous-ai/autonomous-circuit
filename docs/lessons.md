# The defect ledger

Every blocking defect we have hit on a real board, and **where the fix landed**.

The three example boards are the first three boards, not the deliverable. What
they are actually for is finding defect classes before a user does. So a defect
is not closed when the example stops failing — it is closed when a *future*
board cannot hit it.

Four places a fix can land, in descending order of value:

| Where | What it buys |
|---|---|
| **Planner** | the board can't be designed wrong in the first place |
| **Block / skeleton** | every board inheriting it is correct by construction |
| **`circuitlib`** | the number is right everywhere it is used, one owner |
| **Check only** | we find out afterwards, every time, forever |

**Check-only is not a fix.** It is a smoke alarm. A defect that is only detected
is still shipped by every user who ignores a warning, and still costs a build
cycle for every user who doesn't. It stays **open** in this ledger until it
moves up the table.

`scripts/shift-left-check` verifies that every fix claimed below actually exists
in the tree, and fails if one has been reverted or was never landed.

That is worth stating precisely because ledger #6 says tscircuit "SKIPS AUTOROUTING FOR THE WHOLE BOARD" when the 10mm crystal maximum cannot be met — measured today it warns and routes, so #6's claim is either net-specific or overstated, and the block's own comment ("every endpoint within 9.1mm of XIN") is not true of XOUT. | rp2040-core bench; terminal-keyboard, hydrate-coaster | **Block** — put R11 inside the 10mm radius of XOUT rather than beside the crystal, and re-measure the route (#28 method: quote the lever with its blocking count). Until it moves, the suite that is supposed to make the library trustworthy is red, which is worse than the trace. |
| 42 | **A build does not use the checks in the tree, and nothing says so.** Two separate mechanisms, both of which hand back a packet with a fresh mtime and a verdict from a ruler that no longer exists. (a) *The cache does not know the ruler changed.* `_unchanged_prior_result` keys the idempotent short-circuit on the board's source fingerprint and the toolchain block — not on the check set — so fixing a check leaves every existing packet claiming what it earned under the old one, and a rebuild "correctly skips". The reverse is worse: a check that starts *catching* something re-judges nothing until a board's source happens to change. (b) *The pipeline that runs is a vendored copy.* `skills/circuitcode/scripts/packages/circuitpy/` is a generated copy of `packages/circuitpy/src/circuitpy/`, and it is what the CLI imports; `scripts/dev.sh` re-vendors on start but a direct build does not. Measured while closing #41: with the fix in the source and `CIRCUIT_FORCE_REGEN=1` set, a full 905-second rebuild returned **the identical blocking finding**, because the worker was running 2026-08-15's checks — the artifacts were fifteen minutes old and the verdict was a day old. Both are north-star's "every number carries the ruler it was measured with", from the side nobody watches. | terminal-keyboard, 2026-08-16 | **Pipeline** — put the check-set identity (the same hash the agent eval already prints) into the short-circuit key beside the source fingerprint and the toolchain block, and make the vendored runtime's identity part of it too, so a build either uses the tree's checks or refuses. Until then: `scripts/build/build-skill-runtimes.sh` then `CIRCUIT_FORCE_REGEN=1`, by hand, which is exactly the advice-a-user-has-to-remember this ledger exists to eliminate. |

Ink on a solderable surface stops the joint wetting, and JLCPCB clips it. | all three | **Block / layout.** The floor is not negotiable, so the text has to move: reference designators want a placement clear of the part's own pads, which is a footprint and `circuitlib.layout` question, not an exporter one. ## What these three boards taught about checks themselves

Not defects in a board — defects in the *way we look at boards*. Both were
caught before shipping, and both would have been invisible afterwards.

| # | Lesson | How it surfaced | What changed |
|---|---|---|---|
| A | **A check that cannot parse a shape silently passes it.** Our gerber reader could not evaluate parameterised aperture macros (`RotRect`, `RoundRect` — defined once, given their real numbers at each `%ADD%`), so it assigned them zero size and dropped them. **56 of 230 mask openings on harness-puck — a quarter of the layer, and every fine-pitch QFN pad — were never examined.** The sliver count went from "2" to the true 10 once they were resolved. | measuring a fix's before/after and finding the two numbers incomparable | macro parameters are substituted and rotation applied; nothing is dropped for being unparseable |
| B | **A fix can blind its own smoke alarm.** Setting `solder_mask_min_width` made KiCad plot the mask as 223 filled regions instead of 174 flashed apertures. The check only understood flashes, so it would have reported a clean mask on every board where the fix had been applied — quiet, not clean. | re-running the check on the fixed packet before believing the fix | the reader handles both representations, and the setting itself was **retracted**: measured against the same yardstick it removes no web at all, and costs an 8x slowdown. A change that alters the representation and not the board is a placebo |
| C | **A finding is a claim, and the first thing to do with it is measure it.** "Via inside SMD pad" was read as a router defect and answered with router work — effort levels, clearances, `allowViaInPad`, freerouting, a ground plane, and a nudge script that created six shorts. None of it could have worked: the via named by the finding was 0.3009mm outside the pad named by the finding, and no via on the board was inside any pad. Twenty lines of Python over the artifact of record said so in under a minute, and would have said so on day one. | measuring the two coordinates in the message against each other before touching the router | every via-in-pad claim is now re-measured against the geometry, and one whose own numbers disprove it is dropped with the reason recorded (#33) |
| E | **A repair pass graded by its own model is exactly as right as its model.** The differential-pair pass measured every clearance rule it knew — copper to copper, copper to drill, drill to drill, edge, keepout, pour — refused anything that broke one, passed its own unit tests, and turned a `fab.ready` board into a board with 14 blocking findings. The rule it did not know was the *cross* term: one via's pad against another via's drill, 0.196mm against a 0.20mm floor. Nobody would have written that rule down, because it only exists where two vias of one net sit at a pair's pitch. | running the whole pipeline on the pass's output instead of trusting the pass's own verdict | the pass takes a `grade` callback and the pipeline hands it the real gate; the rewrite is kept only when it adds no blocking finding the original did not have, and a grader that raises is a refusal. Every repair that writes copper should be held this way |
| F | **An absent value is a claim, and nothing checks a claim nobody makes.** Three defects on one day, one shape. The BOM's Footprint column was empty on every board ever shipped, because the catalog resolver pointed at a directory that has never existed and returning `{}` was documented as "the honest answer" (#43). The pair pass refused to reserve a corridor because a list it read was the wrong list, and an unexplored option leaves no trace at all (#45). And `schematic_symbol_short` fired on two buttons on all three boards for two days and was written off as noise, because one of the two artifacts it could have meant was clean (#44). Every check we have fires on a value that is *present and wrong*. None of them can fire on a column that is blank, an option nobody tried, or a warning somebody explained away — and those are exactly where a system that measures itself goes blind. | asking what each empty field, silent code path and dismissed warning would look like if it were broken, rather than what it would look like if it were fine | a missing catalog now warns with its consequence instead of blanking a column; the corrected obstacle reading is written into the file that got it wrong; and a check that fires on every board is treated as a finding until the *artifact the reviewer actually opens* is measured, not until one artifact is clean |
| D | **A determinism harness called an empty route reproducible.** The first thing `run_repeat.py` was pointed at was harness-puck, and it reported *route bytes IDENTICAL* over three runs. The board had routed nothing: a courtyard overlap (Y1 against SW1) makes tscircuit skip autorouting for the whole board, so circuit.json carried zero `pcb_trace` and zero `pcb_via`, and the sha256 of nothing is stable forever. It is lesson A one level up — the ruler could not see the shape it was measuring, so it passed it. | pointing the new ruler at a board before checking the board | the harness refuses to report on a run with no copper or a `pcb_autorouting_error`, prints the build's own messages, and exits non-zero; every report now carries the effort level, the copper count and the load average it was taken at |
| G | **One severity policy, two callers, and only one of them ran it.** `pcb_trace_too_long_warning` reaches the verdict twice: `harvest_circuit_json` reads the element out of circuit.json and grades it `warning` from its own suffix, and `run_tscircuit_checks` reports the identical finding out of `@tscircuit/checks` and grades everything it returns `error`. That is fine, because `generation._scan` ends with `checks.dedupe`, whose first-occurrence-wins keeps the harvested copy — the policy is not in either leg, it is in the *order* plus the dedupe. So a second caller that collected the same legs and skipped the dedupe got a different answer from the same artifact: the IDE's `board_fast_check` called **all three shipped boards `blocked`** while their sidecars said `fab.ready: true`, over two findings whose own kind ends in `_warning`. The tell was there in the word and nobody read it. | building a second consumer of the same check legs — the sub-second edit gate — and pointing it at a board the build had just called clean | the gate deduplicates with the build's own function rather than re-grading anything, because the ordering that decides which copy survives is the build's; and where a leg cannot run at all (no `product.json`) the gate reports the leg it lost instead of raising, since "the answer went away" is the one response a gate may not give |
| H | **A unit test proves a piece works; nothing proved the app reached it.** Five instances, four of them inside one day, all the same shape — code that compiles, passes its own tests, gets written down as landed, and is called by nothing. `board_fast_check`, the whole legality gate, with no client caller. `onPlacementRotate`, passed as a prop the component never declared. `PadHeader`, a real block that existed only under a name (`DebugPort`) no engineer would search for, so two of them hand-copied its internals. `editEngine.js`, 687 lines and zero importers. And `app_set_effort` — settings key, driver `--effort`, three phases of the review loop — while the composer's pill wrote to localStorage and appended a prompt directive, so the pill read "Max" and every turn ran at the CLI's default. Both sides of every one of those joins were green. The tell is that a *join* is the one thing a unit test cannot cover, because covering it is what integration means, and we kept writing the two units. | asking, after the third one in a day, what the first two had in common — and then asking the same question of the command table rather than of a memory | `viewer/src/server/circuit/commandsAreWired.test.mjs` reads the server's command table off `http.mjs` and asserts every name appears in shipping client code (tests excluded — a command called only by its own test is the bug), or sits in an `AGENT_ONLY` map **with a written reason**. Deliberately a string search, not a call graph: half the client reaches the API through `transport.ts` and half through a bare `fetch("/api/<cmd>")`, and a check that understood only one would be blind exactly where the last bug was. It found `app_set_effort` the first time it ran. The same question is still open one layer out — a *block* nothing composes, a *check* no gate calls — and wants the same kind of ruler. |

## The rule

When a board fails and an agent fixes it, the question is never "is the board
fixed". It is **"why did the first composition get this wrong, and what stops
the next one"**. The fix belongs in the planner, the block, the skeleton or
`circuitlib` — never in advice a user has to remember, and never only in the
example that happened to catch it.

A block that needs correct handling to be safe is a block that will be handled
wrong.
