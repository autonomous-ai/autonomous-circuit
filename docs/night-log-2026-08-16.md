## The finding of the night: the via-in-pad defect was never real

I spent most of yesterday chasing a via sitting inside J1's USB-C VBUS pad. It was a phantom,
and the cause is worth knowing.

The pad polygon is written **closed** — the last vertex repeats the first. That is a
zero-length edge, and `@tscircuit/checks` decides "is this via inside this pad" with
`isPointOnSegment`, which on a zero-length segment returns true for *every point in the
plane* (`dot = 0`, `len² = 0`, so `0 <= 0 + 1e-9`). **The pad swallows the whole board** and
the spatial index hands it whichever via happens to share its grid cell.

Measured: 108 vias × 174 pads → **0 actual containments**. The named via clears the named pad
by 0.0008692 mm, on the outside. harness-puck and terminal-keyboard carry the same four
closed rings and passed only because none of their vias landed in the same bucket.

Fixed in two places: the rings opened in the golden block (geometrically a no-op — same
polygon, one fewer vertex), and a new **stage 0a** normaliser that opens any closed ring in
compiled circuit.json before anything reads it, then drops only the placement error its own
edit falsifies, judged on bbox containment so a genuine via-in-pad can never be dropped.
Imported EasyEDA/KiCad footprints close their rings routinely, so this protects every future
board.

**The lesson, recorded as ledger entry C:** a finding is a claim. The message contained both
coordinates. Measuring them against each other would have taken one minute on day one, and
would have saved most of a day of routing theories.

## The router tournament finished — 10 agents, no failures

Ten agents, 16 benchmark instances, 13 routers, 208 scored cells. Full write-up in
`docs/architecture/routing.md`. Four results worth your morning:

**1. Determinism is solved.** 208/208 byte-identical, re-verified in a fresh process with
`PYTHONHASHSEED=random`. Every family. That was the thing we did not have and could not
regression-test against; we have it now.

**2. Every self-reported number reproduced exactly.** The judge re-derived all 208 cells and
found **zero disagreements** on completeness or vias. Seven agents marking their own homework
and none of them shaded it.

**3. The adversarial pass earned its keep: our scorer was wrong, and the ranking inverts.**
`rect_capsule` models pads *and keepouts* as their inscribed stadium, so each corner of a 1.0mm
square pad protrudes **0.21mm** — against an 0.09mm gate. Worst measured case: the model
reports 0.210mm of clearance while the trace sits **0.250mm inside the pad**. Harness-clean
routers turn out to be pipeline-dirty:

| router | harness-clean | pipeline-clean |
|---|---|---|
| plane-and-classes | 7/12 | **1/12** |
| maze-astar | 7/12 | **1/12** |
| exact-and-structured | 4/12 | **3/12** |
| baseline-pattern | 2/16 | **3/12** |

The routers *design to* that model, so fixing it should make them route better, not just score
honestly. An agent is on it now, including re-scoring all 208 cells against the corrected
ruler.

**4. The incumbent still wins, and we say so.** On all three real boards the shipped router
beats our portfolio, and worse in kind on our side — its 17 findings are all one benign class,
ours are shorts and clearance. `CIRCUIT_ROUTER` is wired but **off by default**. We are not
shipping a worse router to be able to say it is ours.

Two findings that stand regardless of the pad fix:

- **Selection is a negative result, honestly reported.** No feature rule beats "always use
  pathfinder-negotiated" — all four intuitions we had were measured false and are pinned in
  `REJECTED_RULES` with the killing measurement. One feature does predict *difficulty*: ≤14
  nets, someone finishes (8/8); ≥21 nets, nobody ever has (6/6).
- **Composition works where selection did not.** Relay — lead router first, then each follower
  gets only the still-unconnected nets with existing copper as obstacles — reaches **98.0%**
  mean completeness against 94.0% for the best single family, and beats the hindsight oracle
  of all nine (95.7%). Naive merge was tried first and bought zero nets for 575mm of copper.

## The scorer was lying to the routers, and fixing it made them route legally

This is the result of the night. The judge found `rect_capsule` modelling pads as inscribed
stadiums; the fix went in; **the routers were not merely being mis-scored, they were designing
to the lie.** Told the truth about pad geometry:

| family | KiCad copper errors, broken model | corrected model |
|---|---|---|
| maze-astar | 213 | **0** |
| pathfinder-negotiated | 80 | **0** |
| exact-and-structured | 29 | **0** |

maze-astar pays **0.2 completeness points** for that (324 → 325 nets — it actually routed one
more). pathfinder pays 12.8 points, which reorders the family ranking for a second, better
reason: not the ruler changing, but how each family responds to honest obstacles.

Three numbers that say the benchmark is now a benchmark:

- **Harness-vs-KiCad rank correlation: 0.00 → +0.93.** It predicts reality now; before, it
  predicted nothing.
- **An independent checker sharing no code with the geometry it checks** went from missing
  3–137 findings per router to **0 across all fourteen**.
- Harness-clean cells fell 42 → 17. The hidden findings were 1854 clearance, 587 shorts, 520
  via-in-pad, 68 keepout. All were always there.

Also closed a genuinely nasty one: a polygon pad written back without its `points` made
`runAllChecks` **throw and return an empty list that reads as clean**. Twelve of sixteen
instances carry a USB-C receptacle. Every report now carries a `complete` flag and an
incomplete report is dropped rather than counted as zero — a lost report must never be
indistinguishable from a good one.

Ruler moved `b3c77d55b171` → `56d69c365a72`. Every number above is a **new baseline**, not an
improvement over the old ones — different check set, not comparable, per the north star.

**Open as of this writing:** whether we now beat the shipped router. We lost on all three
