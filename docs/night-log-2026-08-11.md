# Night log — 2026-08-11

What changed while you were away, what it measures, and what I would do next.
Five minutes.

## The short version

The bar moved from "a board that builds" to **"a board you can send to
JLCPCB, first try"**, and this session was about making that a number rather
than a hope.

Three things now exist that did not:

1. **The agent eval** (`evals/agent/run.py`). Eight cold briefs, an empty
   directory each, no human turn, scored on **first-build fab-ready rate**.
   Everything else in the repo measures the pipeline starting from a board
   somebody already wrote; this measures the product. **No headline number
   yet** — see below.
2. **The composition matrix** (`evals/composition.py`). Every legal
   combination of golden blocks, built as a real board through the real
   pipeline. Each block already passed its own gauntlet — no *combination*
   ever had.
3. **The failure corpus** (`packages/circuitpy/tests/test_failure_corpus.py`).
   Every real defect, permanently, each paired with the legal geometry just
   the other side of the line.

## What the matrix found, and it was not small

First run: **6 of 42 compositions clean — 14%.** The failures were almost all
`pcb_component_outside_board_error` and `dfm_edge_clearance`: parts hanging off
a board that our own helper had just sized.

The cause was in `circuitlib.layout` — **the placement advice the skill gives
every agent**. It stored each block's *size* and assumed the geometry was
centred on the block's origin. It is not:

| Block | Its copper sits |
|---|---|
| `usb-c-power` | 3.29mm above its origin |
| `usb-c-data` | 6.04mm above |
| `rp2040-core` | 5.51mm below |

`status-led`'s own testbench places it at `pcbY={-1}` for exactly this reason,
and nobody had followed the thread. `rp2040-core`'s stored height was also
2.6mm short of the truth. So every board built on our advice was wrong by
millimetres before anyone wrote a line of TSX.

Now the table is a measured **box** relative to the origin
(`evals/measure_block_boxes.py` produces it from real builds), and
`place_board()` plans the whole board: connectors on the bottom edge facing
out, mounting holes in a reserved strip so a drill never lands on a footprint,
an outline sized to hold all of it — and it returns its own warnings, so the
plan can be checked before anything is built.

**Closure went 14% → 56%** on that change alone.

### And a second, larger one: the router needs a halo

`rp2040-core` still failed **alone**, on the 43.4 x 27.5mm board our own helper
had just sized for it: five vias *outside the board boundary* and tracks at
0.000mm from the edge. A 5x routing pass did not help — 38 blocking errors both
times. The router was not failing to try; it had nowhere to go.

Four millimetres per side and the same block came back **clean and
fab-ready**. So `EDGE_MARGIN_MM` (1.5mm, a courtyard question) and
`ROUTER_HALO_MM` (4mm, a routing question) are now different numbers, and
`place_board` sizes the outline off the second. `rp2040-core` appeared in six
of ten matrix failures at that point.

### Where the number stands

| Run | Closure |
|---|---|
| pairs + spine, original layout | 6/42 (14%) |
| pairs + spine, measured boxes | 23/41 (56%) |
| singles + pairs + triples + spine, `place_board`, pre-halo | 42/76 partial (55%) |
| same, with the router halo | **50/81 partial (62%)** — run interrupted |

Two honest caveats on the last two rows. They are **partial**: both runs were
stopped, the second deliberately (see below). And `usb-c-power` was being
edited by another agent throughout, so the same cell passes in one run and
fails in the next — a block under active repair is not a stable measurement.
The full number wants a clean re-run on a quiet machine.

## The dial nobody had turned

> **Correction, later 2026-08-11:** the comparison below is invalid. Core's
> route-cache key omitted effort and pipeline configuration, so nominally
> different runs could reuse the same cached copper. The cache identity and
> pipeline retry isolation are now fixed, but these numbers must not be cited
> as evidence that `5x` improves route quality. This section remains only as a
> contemporaneous record of how the false conclusion was reached.

`autorouterEffortLevel` is a `<board>` prop with five settings and no CLI flag.
We had never set it, so **every board this project has ever built routed at the
default.**

| Board | default | at `"5x"` |
|---|---|---|
| terminal-keyboard | 46 blocking errors | 18 |
| harness-puck | 5 | **1** |

No design change in either case. The cost is time: harness-puck took 1240s at
5x against about 90s at the default.

A higher fixed default would charge every simple three-block board twelve
wasted minutes, so the pipeline now **escalates once** — only when the errors
are routing-class, and it keeps the cheaper result unless the harder one is
strictly better. The attempt is reported in the sidecar (`build.autorouterEffort`),
because a silent seventeen-minute build is its own kind of bad.

One consequence that survives the correction: **the skill's wall clock had to
go from 300s to 2700s.** Cold dense routes plus independent KiCad verification
can legitimately take minutes. The longer ceiling does not imply that greater
router effort is better; every alternate result must finish and beat the first
parsed artifact.

### Two board props that look like routing levers and are not

Measured, so nobody retries them:

| Prop | What it did |
|---|---|
| `minTraceWidth` / clearance raised | 7 errors → **125** |
| `minBoardEdgeClearance="0.5mm"` | 0 errors → **8** |

Both **gate the checker, not the router**. Raising one does not move a single
track; it only moves the line the tracks are measured against, so a board that
passed now fails. This is the preference-as-floor mistake wearing a different
hat, and it has now been made three times in two days.

What *did* fix the edge-hugging tracks was room: the same board on an outline
8mm larger in each direction came back **0 blocking, fab-ready**. Which is
exactly what `place_board()`'s margins and hole strip give you for free —
`ldo-3v3 + rp2040-core` went from blocked to fab-ready with no other change.

## SPICE, tried properly and rejected

`tscircuit-cli simulate analog` is the toolchain's own path and had never been
evaluated. On harness-puck it ran for **3 minutes 24 seconds** and ended in
`run simulation(s) aborted`: singular matrix at node `n3`, transient timestep
collapse at the LED, and **nodes still anonymised to n1/n3** — the exact
blocker that shelved `spice_smoke.mjs`.

It cannot name a rail, so it cannot tell you a rail is at the wrong voltage.
Wiring it in would add a check that always finds nothing while implying
coverage of the one class we are blind to. **Not wired in**, and the reason is
in `docs/meta-improvements.md` so the next person starts from the measurement.

The honest next attempt is a rail-graph check over `circuit.json` connectivity
— identify each declared rail, verify it has exactly one source, check divider
ratios against their declared output. Arithmetic we own, not a simulator we do
not.

## What is now enforced

- **`fab.ready: true` is the definition of done.** Not "clean build", not "no
  blocking warnings". The circuitcode done-gate is literally `fab.ready ==
  true` and the final response leads with it. `fab.ready: false` is an
  unfinished board, not a finished one with caveats.
- **The design-review panel is not optional.** It is the last stage of every
  board, not something a turn remembers to call.
- **Closure under composition** is in the frozen contract: anything the planner
  can legally emit must be inside the tested space.
- **The examples are ratcheted** (`evals/examples_lock.py`) — a board may get
  better, never worse.

## The headline number: not yet, and why

The eval ran twice and neither run finished.

What it did produce, from the one brief that completed end to end
(`usb-blinky`, "a tiny USB-C board with a light that shows it has power"):
**three builds, first build not fab-ready, final build fab-ready.** So
first-build fab-ready = 0 of 1, final = 1 of 1. One brief is not a rate.

Two things the attempts taught, which are worth more than a number from a
broken run:

* **The agents use the corrected placement API and reason in millimetres from
  it.** usb-blinky's board file argues its own floorplan out of
  `usb-c-power`'s measured box, down to why it has no mounting holes. That is
  the shift-left work landing.
* **Raising the build budget traded one failure mode for another.** One brief
  ended its turn with *"Waiting on the structural check to return its
  verdict"* after 43 turns. A build that can now take twenty minutes outlasts
  the agent's own patience, and `scripts/check` throws its artifacts away, so
  a session can compile five times and leave no verdict behind. The harness
  now counts attempts from `build-status.json` rather than from sidecars, and
  writes its report after every brief — the first run lost eight results to a
  kill at brief seven.

## Open, honestly

- **The remaining composition holes.** After the placement fix and the extra
  room, the survivors are dominated by one cause: `dfm_hole_clearance` on every
  `usb-c-data` pairing — the connector footprint, block-owned and being fixed
  separately. Two blocks also fail *alone* in the exhaustive run
  (`usb-c-data`, `rp2040-core`), which is a block-level finding, not a
  composition one.
- **No board has ever been fabricated.** Every block is compile-verified, none
  hardware-verified. First-pass yield in the real world is still unknown.
- **`gerber_drill_empty` blocks a correct board.** `packages/verify`'s
  `_drills_match` fires when a drill file has no hits *without checking that
  the design has any holes*, so its own message reads "the drill file has no
  hits, but the design has 0 holes". It is in `VERIFY_BLOCKING_KINDS`, so a
  hole-less board can never be fab-ready, and it currently reddens
  `packages/circuitpy/tests/test_build_board_e2e.py`. One condition in
  `gerber_truth.py:250` (`or not packet.drills` needs
  `or not (board.vias or board.holes)`). Not my file, so flagged rather than
  fixed.
- **Nothing checks tolerance corners.** Every resistor is ±1%, every capacitor
  ±10%. A divider that is fine at nominal and out of spec at 3-sigma passes
  every gate we own and then shows up as two boards out of five behaving
  differently.
