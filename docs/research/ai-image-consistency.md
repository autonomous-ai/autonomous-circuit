=== WHAT OUR ENGINE ACTUALLY DOES TODAY (gap analysis) ===
File: /Users/d/code/autonomous-tv/packages/dramapy/src/dramapy/providers/cinematic.py
- Character reference = exactly ONE portrait per character, generated by fal-ai/flux-pro/v1.1-ultra (a 2024-era t2i model), cached, reused for every shot.
- Keyframe = fal-ai/bytedance/seedream/v4/edit placing that single ref into the scene; no-cast shots fall back to the old Flux t2i.
- i2v = fal-ai/kling-video/v2.5-turbo/pro/image-to-video.
- cast-book skill already SPECIFIES the correct industry asset — the four-view turnaround sheet (1/4 head close-up + front/side/back full body on white + expression, naming 人名_特征) — but "v1 generates reference PROMPTS, not images." So the consistency system is prompts-only; nothing renders the sheet, and the keyframe edit only ever sees one image.
- No world/set/prop reference assets (production-design skill is "planned"); no style/color bible; colorist stage "planned."
This aligns with our own drama-research (docs/drama-research-2026-08-09.md): 4-6 refs/character, scenes 场景名_特征, prop library, "consistency is the #1 dropout driver (92% drop on visual discontinuity)." We wrote the spec and haven't wired the pixels.

BOTTOM LINE: our single-ref, Seedream-v4 keyframe pipeline is ~3 consistency generations behind. Nano Banana Pro (14 refs, 5 faces, 4K, real text) and FLUX.2 (10 refs) are purpose-built for exactly the multi-reference turnaround-sheet workflow our cast-book already prompts for. The fastest quality jump available to us right now is to render the sheets we already spec and feed a STACK of references into a Nano-Banana-Pro/FLUX.2 keyframe edit — cast + set + prop + style in one 14-image budget.
